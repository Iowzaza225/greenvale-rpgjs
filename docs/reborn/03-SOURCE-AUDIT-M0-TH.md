## Specific failure risk we can prove from code
1. **Atlas-test ≠ gameplay animation-test.** Current test samples pixels from animation banks, not real actor sprites while walking/attacking/death.
2. **Branch divergence:** mobile arts vs desktop/map are separate sibling branches after phase 4. Integrating without explicit cutover tests can regress controls or boot.
3. **The art is procedural:** even with 9 action banks it may still appear as pasted/doll-like art; must evaluate live action frames on device, not promise final Smooth Fantasy quality.
4. **Gameplay scope mismatch:** PR #17 maps.json contains only camp; desktop world has five maps. An incomplete merge can show UI/warps for maps that are not in that branch.
5. **Safe-zone inconsistency:** PR #15 docs say training wolves still spawn at camp despite safeZone metadata. MVP requires deliberate safe spawn and isolated fight area.

## Exact import order / changes on next implementation branch (NOT DONE)
1. Create independent implementation branch from **the proven phase/4 baseline** (rather than merge entire divergent PRs); first commit pins exact source commit and dependencies.
2. Make a single small scene that boots iPhone WebKit and Chromium; use existing RPGJS renderer with a **thin unified input adapter**. Do not copy large desktop UI.
3. Wire just Novice + Ashfang Wolf to a typed actor animation bridge. Source the procedural sprite atlas as a **clearly marked temporary reference** to test logic.
4. Add real interactive tests that read the actor's **visible action/state and frame index** after movement/attack/hit/death, not just generated atlas content.
5. Add deterministic combat contact and range tests; require attack animation frame progression and damage event to agree.
6. Port only tested desktop keys and tested single-map depth/collision; ensure blur resets input, death resets state and no duplicated handlers.
7. Run build, browser automated tests and manual iPhone+PC loops. Open a separate Draft PR; do not merge before manual approval.

## Test scenarios (expected)
- Idle -> walk -> idle: sprite frames change while input held and stop correctly; facing matches direction.
- Attack in range: attack frame changes and damage lands in action hit-window. Out of range: HP unchanged.
- Wolf aggro -> chase -> strike -> defeat; no duplicate mobs or stale targets.
- Player death -> respawn: one transition each; safe spawn; input and renderer recover.
- Keyboard focus lost / touch cancel: no stuck movement; browser shortcuts do not fire while typing.
- Colliders use ground-foot footprint; depth sorting uses ground-foot Y.
- Repeat 10 encounters, 10 min on real devices. No severe performance degradation or fatal overlays.
