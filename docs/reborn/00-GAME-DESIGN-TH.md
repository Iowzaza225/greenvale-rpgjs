# GREENVALE AFTERFALL — REBORN
## Game Design Document (GDD) v0.1 — 16 October 2026

**สถานะ: Design proposal / ยังไม่ใช่ตัวเกมที่ทำเสร็จ**
**ขอบเขต:** Mobile Safari + Desktop browser, เกมภาษาไทยเริ่มต้นและสลับอังกฤษได้, RPG มุมเอียงแบบ 2.5D Smooth Fantasy (ไม่ใช่ 3D จริง ไม่ใช่ pixel art)

### 1. เป้าหมาย
สร้างเกม Greenvale Afterfall ที่เล่นได้จริง มีความรู้สึกของโลกแฟนตาซีหม่นหลังเหตุการณ์ล่มสลาย เน้นการเคลื่อนไหวที่มีชีวิต สู้ได้ตรงจังหวะ และตอบสนองดีบนมือถือกับคอมพิวเตอร์ ก่อนเพิ่มเนื้อหาหรือฟีเจอร์จำนวนมาก

คำจำกัดความของ 2.5D สำหรับโครงการนี้: ตัวละคร/มอนสเตอร์เป็น animated sprite แบบ smooth non-pixel art ที่เดินอยู่ในฉากมุมเฉียง มีวัตถุสูง การบังหน้า/หลัง (depth sorting) เงาและ collision ตรงกับภาพ ไม่ใช้ภาพนิ่งก้อนเดียวแทนแอนิเมชัน

### 2. Gameplay loop ฉบับพิสูจน์ระบบ
เกิดใกล้เขตปลอดภัย -> เรียนรู้การเดิน -> เล็งมอนสเตอร์ -> เข้าระยะ -> โจมตีพร้อมภาพฟันจริง -> ลด HP มอนสเตอร์ -> ศัตรูโต้ตอบ -> ได้ผลลัพธ์ชัดเจน -> กลับจุดเกิดได้เมื่อแพ้

**MVP v0.1 (vertical slice เท่านั้น):**
- แผนที่เล่นได้ **หนึ่งพื้นที่**: สนามฝึกนอก Greenvale ที่มีจุดเกิดปลอดภัยและพื้นที่ต่อสู้; ยังไม่อ้างว่า Greenvale Camp เดิมเป็น safe zone เพราะยังมี training wolves ในโค้ดเดิม
- **หนึ่งตัวละคร Novice** ที่เดิน/หยุด/หัน/โจมตี/โดนโจมตี/ตาย/เกิดใหม่พร้อมภาพเคลื่อนไหวตรงกับสถานะจริง
- **หนึ่งศัตรู Ashfang Wolf** แบบเคลื่อนไหว: idle/walk/attack/hit/death, ตรวจเจอผู้เล่น, เดินไล่ตามในระยะ, ตีเมื่อถึงระยะ, ไม่สะสม spawn จนล้น
- การโจมตีธรรมดาหนึ่งแบบและสกิลทดสอบหนึ่งชนิด (ถ้าระบบโจมตีพื้นฐานเสถียรแล้วเท่านั้น)
- HP ผู้เล่นและศัตรู, หมายเลขความเสียหาย, ปุ่มเลือกเป้าหมาย, ตอบสนองเมื่อโจมตีพลาด/พ้นระยะ
- ระบบ respawn ไม่ค้าง ไม่ชนกับสถานะ death และกลับมาควบคุมได้
- UI สำหรับจอสัมผัสและเดสก์ท็อป: ขนาดปรับตามพื้นที่, ไม่ทับพื้นที่เล่นสำคัญ
- เซฟข้อมูลทดสอบแบบ Guest ในเครื่องโดยแยก namespace เวอร์ชัน REBORN; ไม่ลบเซฟเดิม ไม่อ้างว่าซิงก์ข้ามอุปกรณ์
- ไทย/อังกฤษสำหรับข้อความที่มีใน vertical slice

**จงใจไม่ใส่ใน v0.1:** 7 อาชีพ, 11 มอนสเตอร์พร้อมกัน, แผนที่ 5 โซนพร้อมกัน, ร้านค้า, อุปกรณ์หลายชิ้น, pet/forge/dungeon, online multiplayer, ระบบช่อง 1–3 แบบผู้เล่นร่วมกัน, ระบบสร้างตัวละครเต็มรูปแบบ, boss เต็มรูปแบบ

### 3. Gameplay rules / combat
- การเดินและ hitbox ใช้พิกัดเกมจริง ไม่ใช้ตำแหน่ง sprite ใน DOM คำนวณดาเมจ
- การโจมตีผ่านสถานะ wind-up -> active hit window -> recovery; damage ลงเมื่ออยู่ใน hit window ตามกติกา ไม่ใช่แค่กดปุ่มแล้วภาพแสดงทีหลัง
- มี attack cooldown ป้องกันยิงคำสั่งรัว; การหยุดเดิน การสตัน และการตายต้องยกเลิกคำสั่งไม่ถูกต้อง
- เป้าหมายพ้นระยะให้เดินเข้าหาเฉพาะเมื่อเลือก auto-approach; โจมตีเกินระยะไม่สร้าง damage
- ศัตรูเปลี่ยนสถานะ idle -> pursue -> attack -> return/death; จำกัดจำนวนศัตรูและไม่ spawn ซ้ำเมื่อเปลี่ยนแมพ
- ไม่มีการตายซ้ำหรือเข้า animation dead ซ้ำจนเกมค้าง

### 4. Art direction
- โทน: post-apocalyptic dark / smooth fantasy / แสง เงา และพื้นผิวไม่เป็นพิกเซลหยาบ
- มุมกล้อง 2.5D oblique/isometric-like **คงที่** ใน v0.1 เพื่อควบคุมระยะ/การชน/การบัง
- ตัวละครต้องใช้ชุดเฟรมแอนิเมชันจริง ไม่ใช่ภาพเดียวที่ขยับทั้งชิ้นด้วย CSS
- ขั้นแรก 4 ทิศ (N/S/E/W) โดยระบุอย่างเปิดเผย; 8 ทิศเป็นเป้าหมายภายหลังเมื่อ asset/งบประสิทธิภาพพร้อม
- ขั้นแรกใช้ชุด idle / walk / attack / hit / death; run/cast/rest/emote เพิ่มหลังระบบ trigger ใช้ได้จริง
- ทุกการโจมตีต้องมีการเปลี่ยน silhouette/อาวุธและ impact feedback ที่สังเกตได้ชัด
- เนื้อหาภาพและชื่อสร้างเองทั้งหมด; ไม่ยืมภาพ เกม หรือแบรนด์ภายนอกที่ไม่ได้สิทธิ์

### 5. Input / HUD
| คำสั่ง | Mobile | Desktop |
|---|---|---|
| เคลื่อนที่ | joystick ซ้าย | WASD / ลูกศร |
| เล็งเป้าหมาย | ปุ่ม target/แตะศัตรู | Tab / คลิก |
| โจมตีพื้นฐาน | ปุ่ม Attack ขวา | Space / J |
| สกิลทดสอบ | ปุ่มสกิลหนึ่งช่อง | 1 |
| เมนูและตั้งค่า | ปุ่มแตะ | Esc ปิดหน้าต่างบนสุด |

Hotbar 1–0, I กระเป๋า, K สกิล, C สเตตัส, Q เควส, drag-drop แบบต่างแพลตฟอร์มเป็น **requirements ของระยะถัดไป**; ต้องไม่มีปุ่มหลอกว่าเสร็จแล้ว

### 6. Quality goals
- เครื่องทดสอบจริง: iPhone Safari และ desktop Chromium; ทดสอบขนาด 16:9 และ 21:9 เพิ่มเติม
- 5–10 นาทีต่อรอบ ไม่มี error overlay, ค้าง, จอดำ หรือกระตุกผิดปกติจาก spawn
- 30 FPS ขึ้นไปเป็น **เป้าหมายทดสอบเบื้องต้นบน iPhone เป้าหมาย**, ไม่ใช่การรับรองทุกเครื่อง
- แอนิเมชันต้องเปลี่ยนตาม input/status/ตำแหน่ง, การตีโดนมีผล HP ตามกติกา, revive แล้วกลับมาเล่นได้
- ทุก feature ต้องมี acceptance test ไม่ใช่เพียง build ผ่าน

### 7. คำว่า 'สำเร็จ' สำหรับ v0.1
ผู้เล่นเปิดเว็บบนมือถือและคอมได้ เดินหลบสิ่งกีดขวาง มองเห็นเฟรมเดินจริง หันถูกทิศ ตี Ashfang Wolf แล้วเห็นเฟรมฟัน+ผล damage สัตว์ไล่และตอบโต้ได้ แพ้แล้ว respawn และกลับมาสู้ใหม่ได้ โดยทั้งสองแพลตฟอร์มผ่าน automated test และ manual gameplay QA ก่อนนำไปต่อยอด

### 8. หลักปฏิบัติ
ทำหนึ่งส่วนให้ playable ก่อนเพิ่มจำนวน content; feature ใหม่ที่ทดสอบไม่ผ่านต้องถูกแยกไว้ ไม่รวม main; ห้ามบังคับ merge PR #15/#16/#17 หรือเอา sprite prototype ไปเรียก final production artwork
